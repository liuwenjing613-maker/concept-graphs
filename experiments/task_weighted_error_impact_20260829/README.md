# False split / false merge / 语义修复实验总报告

日期：2026-08-30
场景：Replica `room0`、`office0`
结论级别：两场景正式实验；可用于路线判断，但不等同于全数据集统计结论。

## 一句话结论

**仅修复 false split、false merge 和错误语义不能获得大的整体提升，而且明显受到检测/mask、对象完整性、身份纯度与关系质量限制。**

- 含关系项的原始四指标恢复率：`ρ = 0.0128`（1.28%）。
- 去掉混合模型关系项后，仅用实例 AP、节点 F1、语义准确率重算：`ρ = 0.1523`（15.23%）。
- 两者均远低于预设的 `ρ < 0.4` 判据，因此应判定为：**检测/mask 与对象完整性是主瓶颈，不能继续把关联+语义修复作为唯一主路线。**

## 1. 实验设计与严谨性

### 1.1 全量在线 Oracle

两个场景均从空图开始，按在线帧顺序建图到 processed frame 399，不复用未来帧已经建好的图。

| 条件 | 含义 |
|---|---|
| B0 | 当前系统 |
| O1 | 保持当前 mask，仅按 GT 实例身份重组，模拟修复 false split / false merge |
| O2 | O1 + GT 语义 |
| O3 | GT mask + GT 关联 + GT 语义 |

主指标 `Q` 为实例 AP、节点 F1、语义准确率、关系 R@1 的等权算术平均；同时保留调和平均、最小值及关系无关敏感性结果。

### 1.2 客观冻结案例

- 先完成 Pred↔GT 的 2.5/5/10 cm 三尺度匹配和 Error Atlas，再冻结案例，最后才构造 Oracle。
- 冻结 16 例：association 3、semantic 3、spurious 3、geometry 3、control 4；room0/office0 各 8。
- 选择不使用旧人工审计标签，也不使用 Oracle 修复后的结果。
- 关联身份使用逐帧真实 mask 像素重叠，不使用不同条件间不可比较的局部 `mask_idx`。
- 4 个 control 均为 no-op/相对对照；没有通过客观标准的绝对干净对照。
- 正式逐案例评测：12 个非对照案例 × 3 个尺度 = 36/36 成功，0 失败。

## 2. 原全量 B0/O1/O2/O3 结果

### 2.1 每场景 Q 与恢复率

| 场景 | B0 | O1 | O2 | O3 | ρ=(O2-B0)/(O3-B0) |
|---|---:|---:|---:|---:|---:|
| room0 | 0.224542 | 0.143583 | 0.248583 | 0.950000 | 0.033140 |
| office0 | 0.193322 | 0.073112 | 0.187696 | 0.906250 | -0.007892 |
| 两场景宏平均 | 0.208932 | 0.108348 | 0.218139 | 0.928125 | **0.012803** |

关键现象：

- O1 在两个场景都低于 B0，说明“完美重组”本身会改变对象集合和关系候选空间，并不保证端到端变好。
- O2 比 O1 改善，但宏平均只比 B0 高 `0.009208`。
- O3 比 O2 高 `0.709986`，绝大多数可改善空间仍在 mask/检测/完整性及其下游交互中。

### 2.2 四指标宏平均

| 条件 | 实例 AP@25/50 | 节点 F1 | 语义准确率 | 关系 R@1 |
|---|---:|---:|---:|---:|
| B0 | 0.008725 | 0.060574 | 0.071429 | 0.695000 |
| O1 | 0.025292 | 0.134349 | 0.100000 | 0.173750 |
| O2 | 0.025292 | 0.134349 | 0.416667 | 0.296250 |
| O3 | 1.000000 | 1.000000 | 1.000000 | 0.712500 |

O2 确实提高语义准确率，但实例 AP 与节点 F1 仍很低；关系 R@1 还低于 B0。仅修关联与语义无法补回对象缺失和 mask 几何错误。

### 2.3 去掉关系项的敏感性分析

关系预测缓存混合了不同模型，因此另外用实例 AP、节点 F1、语义准确率三项重算。

| 场景 | B0 | O1 | O2 | O3 | relation-free ρ |
|---|---:|---:|---:|---:|---:|
| room0 | 0.086056 | 0.138111 | 0.238111 | 1.000000 | 0.166373 |
| office0 | 0.007763 | 0.034983 | 0.146094 | 1.000000 | 0.139414 |
| 两场景宏平均 | 0.046909 | 0.086547 | 0.192103 | 1.000000 | **0.152340** |

去掉关系模型混杂后恢复率上升，但仍远低于 0.4；主结论不依赖关系项。

## 4. 家族级 Oracle 结果

以下为 5 cm、两场景宏平均、相对 B0 的变化：

| 修复家族 | ΔPrecision | ΔRecall | ΔF1 | Δ平均纯度 | Δ平均覆盖 | Δ语义准确率 |
|---|---:|---:|---:|---:|---:|---:|
| semantic | 0.000000 | 0.000000 | 0.000000 | 0.000000 | 0.000000 | +0.041667 |
| spurious | +0.003478 | 0.000000 | +0.001152 | +0.022989 | 0.000000 | 0.000000 |
| geometry | +0.030704 | +0.024725 | **+0.027458** | +0.012964 | **+0.060288** | +0.062143 |
| association | +0.025137 | +0.005495 | +0.011905 | +0.013433 | +0.001578 | **-0.059524** |
| combined | +0.068544 | +0.030220 | +0.043315 | +0.056840 | +0.061866 | +0.057500 |

解释：

- geometry 是唯一同时稳定提高 Recall、F1、覆盖率的主家族，且 6/6 场景×尺度单元都改善。
- association 家族宏平均看似改善，但语义准确率下降；逐案例检查后只有 1/3 是无明显副作用的严格成功。
- semantic 只改变语义，不改变结构；但冻结集中没有严格纯语义 S1，因此该 `+0.041667` 不能解释成纯语义上限。
- spurious 删除的作用稳定但幅度极小。

## 6. 最高影响家族的因果复核

### 6.1 geometry

| 案例 | O3 可见观测数 | 原始检测支持 | 最终 B0 支持 | 判断 |
|---|---:|---:|---:|---|
| G01 blinds | 149 | IoU≥0.1：20.8% | 7.4% | 检测质量差 + 建图保留损失混合 |
| G02 cushion | 80 | 原始缓存缺失 | IoU≥0.1：0% | 常被 pillow/coffee table 大 mask 吸收；阶段未完全分辨 |
| G03 tissue-paper | 42 | IoU≥0.1：0% | 0% | 检测/mask 漏失主导 |

这些实例并非只“少了一点点”：它们在 O3 中有大量可见观测，而 B0 三尺度 3D 覆盖均为 0。上游实例 mask、对象初始化/保留和相邻对象吸收是主要限制。

### 6.2 association

- A02 是真正可获益的高纯度 false split；安全合并能显著减少碎片。
- A01 的同一节点包含多个 GT 身份，拆分后增加假阳性，收益不稳定。
- A03 虽减少碎片，但混入邻近对象，导致纯度和语义明显退化。
- 因此关联修复必须有纯度门限、不同身份排斥证据和回滚检查，不能仅凭“多个片段对应同一 GT”直接合并。

该结果使用 `gpt-5.6-sol`，没有证据表明 GPT vision 优于 LLaVA caption 路线；两者都被身份/几何错误与词表映射限制。

### 7.2 Terra 对照状态

- 模型列表接口和最小 Terra completion 均成功；最小 completion 明确使用 4,408 tokens。
- 正式多视图语义请求持续返回 HTTP 502。
- 已验证不是并发导致，也不是 300→100 completion token 上限导致。
- 完整 office0 在手动中断前观察到 23 个失败任务；每任务最多 3 次重试，因此上限为 69 次 502 HTTP 尝试。
- 后续三组有界诊断共 6/6 失败，均无 usage 返回。
- 为避免继续浪费，严格的 `gpt-5.6-terra + 服务默认推理强度` 对照已停止；没有用低推理强度或其他模型悄然替代。

因此，Terra 对照是“明确失败/阻塞结果”，不是成功实验，也不能用于比较准确率。

## 10. 最终路线判断

按照预设判据：

- `ρ ≥ 0.6`：强支持继续当前路线；
- `0.4 ≤ ρ < 0.6`：仍值得做，但需证明收益来自真实修复；
- `ρ < 0.4`：检测/mask 已成为主要瓶颈。

本实验：

- 原四指标 `ρ = 0.0128`；
- 去关系敏感性 `ρ = 0.1523`；
- 均 `< 0.4`。

**最终决策：不支持把 false split、false merge 和语义修复作为唯一主路线。**

推荐优先级：

1. 先提高检测/mask 的实例完整性与小物体召回，并审查对象初始化、在线保留和被邻近大 mask 吸收的问题。
2. 关联修复仅对高纯度、跨帧身份一致的 case 启用，并对纯度、语义和关系副作用做回滚。
3. 先构造足够的严格 S1 纯语义案例，再判断语义修复的真实上限；当前 S2/S3 不能支持强结论。
4. 若继续 Terra 视觉对照，需要用户明确允许降低推理强度，或等待/更换稳定的多模态端点。

## 11. 主要局限

- 只有两个场景，适合路线决策，不代表全数据集置信区间。
- 冻结集中无严格 S1 纯语义案例、无绝对干净 control。
- 某些 GT 标签与视觉区域存在本体/映射混淆；结构指标采用 class-agnostic 匹配仍可解释，但语义结论必须保守。
- 关系结果混合 Sol/Terra；已通过 relation-free 敏感性分析隔离该影响。
- G02 缺少原始检测缓存，无法完全区分检测漏失与图保留损失。
- Terra 多视图语义对照因 HTTP 502 未完成。
