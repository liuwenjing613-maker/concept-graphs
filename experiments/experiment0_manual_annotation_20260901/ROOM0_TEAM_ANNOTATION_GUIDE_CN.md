# 实验 0：room0 队友标注说明（简明版）

标注入口：`http://127.0.0.1:18770/`

## 1. 页面整体布局

| 位置 | 内容 | 作用 |
|---|---|---|
| 顶部 | 完成进度、当前案例编号 | 确认自己正在标哪一例 |
| 左侧上方 | 当前 observation 的场景图和 mask 裁剪图 | 先判断当前 mask 包含什么物体 |
| 左侧下方 | 候选 A–E 的历史图和 3D 对比图 | 判断候选是否与当前 observation 属于同一物理实例 |
| 右侧 | 阶段 A、阶段 B 的标注表单 | 依次完成盲标和揭示后裁决 |
| 右侧底部 | 上一例、下一未完成、下一例 | 切换案例 |

图中通常以**粉色表示当前 observation**，**青色表示候选历史**。

## 2. 固定操作顺序

1. 先看当前场景图和 mask，判断 mask 质量。
2. 再比较候选 A–E，判断哪些候选与当前 observation 是同一个现实物体。
3. 填写身份证据状态和必要说明。
4. 点击“保存盲标并揭示 mapper 选择”。阶段 A 提交后不能修改，提交前必须复核。
5. 查看 mapper 原始动作，完成阶段 B。
6. 保存最终标签，进入下一例。

**阶段 A 只能根据图像和事件前历史判断，不能猜 mapper 做了什么。**

## 3. 阶段 A：当前 mask 质量

| 选项 | 什么时候选 |
|---|---|
| `CLEAN_SINGLE_INSTANCE` | mask 清楚地对应一个独立物理实例，边界基本可靠。 |
| `BORDERLINE_SINGLE_INSTANCE` | 仍能确认是一个独立实例，但存在遮挡、只看到一部分、边界略差或视角不佳。 |
| `MIXED_MULTIPLE_INSTANCES` | 一个 mask 同时包含两个或更多可分开的独立物体。 |
| `BACKGROUND_OR_FRAGMENT` | mask 主要是墙、地面、背景，或只是不能作为独立物体识别的零散区域。不要因为物体只露出一部分就选它。 |
| `DUPLICATE_PROPOSAL_SAME_FRAME` | 同一帧对同一物体产生了明显重复、近乎相同的 proposal。只有证据明确时才选。 |
| `DYNAMIC_POSE_DEPTH_ERROR` | 动态物体、位姿错误或深度错误导致图像与 3D 明显错位，身份比较不可信。 |
| `GRANULARITY_AMBIGUOUS` | 无法稳定判断“它是一个独立物体，还是另一个物体的一部分”。必须在实例描述中写清楚争议的整体—部件边界。 |
| `INSUFFICIENT` | 当前图、mask 或相关证据太差，连 mask 属于什么情况都无法可靠判断。 |

### 最重要的区别

- **只看到完整物体的一部分，不等于粒度歧义。**只要现实中仍能看出是一个独立实例，选 `CLEAN` 或 `BORDERLINE`。
- `MIXED` 要求 mask 中确实有多个独立物体，不是一个物体的多个可见部分。
- `BORDERLINE` 是“还能判断”；`INSUFFICIENT` 是“无法可靠判断”。

## 4. 阶段 A：同一物理实例候选

| 选项 | 什么时候选 |
|---|---|
| 候选 `A–E` | 当前 observation 与该候选历史属于现实中的同一个物体。 |
| 多选候选 | 同一个现实物体已经在地图中错误拆成多个节点时，把这些节点全部选上。 |
| `NONE_SHOWN` | 能判断当前实例，但展示的候选中没有一个属于它。 |
| `UNCERTAIN` | 现有视角、历史或 3D 证据不足，无法可靠决定候选身份。 |

`NONE_SHOWN` 和 `UNCERTAIN` 都必须单独选择，不能与 A–E 同时选择。

判断的是**同一个现实物体**，不是同类别：

- 同类别、同颜色、同材质，不代表同一实例。
- 相邻的窗帘、百叶、椅子或柜门，也可能是不同实例。
- 主要结合空间位置、形状、上下文和多帧历史判断。

## 5. 阶段 A：身份证据状态

| 选项 | 什么时候选 |
|---|---|
| `SUFFICIENT_FOR_IDENTITY` | 证据足够，可以稳定选择 A–E 或 `NONE_SHOWN`。 |
| `PARTIAL` | 有一定判断依据，但缺少关键视角或历史，只能做有限判断。 |
| `INSUFFICIENT` | 无法可靠完成身份判断。此时通常选择 `UNCERTAIN`。 |

如果 mask 质量选了 `INSUFFICIENT`，身份证据也必须选 `INSUFFICIENT`。

“物理实例描述”一般可不填；如果选 `GRANULARITY_AMBIGUOUS`，必须说明无法区分的整体与部件。

## 6. 阶段 B：揭示 mapper 后裁决

阶段 A 保存后，页面会揭示 mapper 原始动作：

- `ATTACH(候选 X)`：系统把当前 observation 接到了已有节点 X。
- `NEW`：系统新建了一个节点。

### 6.1 原始 ATTACH 目标在事件前的状态

| 选项 | 什么时候选 |
|---|---|
| `CLEAN_SINGLE_INSTANCE` | 该目标节点在当前事件发生前只代表一个干净的物理实例。 |
| `ALREADY_CONTAMINATED` | 该目标节点在当前事件前已经混入其他实例或已经错误。 |
| `UNCERTAIN` | 事件前历史不足，无法确认目标是否已经污染。 |
| `NOT_APPLICABLE` | mapper 原始动作为 `NEW`。页面通常会自动选择。 |

这里只判断**事件发生前**的状态，不能把当前 observation 加入后的结果算进去。

### 6.2 完整事件时 `t^-` 地图检查结果

| 选项 | 什么时候选 |
|---|---|
| `NOT_NEEDED_MATCH_SHOWN` | 阶段 A 已经选出了正确的 A–E 候选。 |
| `MATCH_EXISTS_OUTSIDE` | A–E 没有正确候选，但检查完整事件前地图后，发现正确节点在展示范围外；同时填写该节点 UID。 |
| `NO_MATCHING_NODE_EXISTS` | 检查完整事件前地图后，确认当时没有任何对应节点，正确动作应为 `NEW`。 |
| `UNCHECKED` | 没有完成完整地图检查，或阶段 A 为 `UNCERTAIN`。 |

**如果页面没有提供完整地图或节点 UID，不要猜 `MATCH_EXISTS_OUTSIDE`/`NO_MATCHING_NODE_EXISTS`，直接选 `UNCHECKED`。**

### 6.3 其他字段

- 因果备注：只写事实，例如“目标在本事件前已经混入另一实例”；不要自己判断 root/cascade。
- 置信度：`5` 非常确定，`4` 较确定，`3` 有依据但有限，`2` 很弱，`1` 基本无法判断。
- 如果身份证据为 `PARTIAL` 或 `INSUFFICIENT`，备注必须写明缺少什么证据。

## 7. 页面最终可能显示的路由结果

这些结果由系统根据两阶段答案自动生成，不需要手动选择：

| 结果 | 含义 |
|---|---|
| `CORRECT_ATTACH` | 系统正确接到了同一实例的已有节点。 |
| `WRONG_ATTACH_EXISTING` | 系统接错了已有节点，但事件前已经存在另一个正确节点。 |
| `SHOULD_HAVE_BEEN_NEW` | 系统错误 ATTACH，事件前没有正确节点，本应新建。 |
| `CORRECT_NEW` | 事件前没有正确节点，系统正确新建。 |
| `WRONG_NEW_FALSE_SPLIT` | 事件前已有同一实例节点，系统却新建，造成错误拆分。 |

## 8. 多人一起标注时

- 开始前记录“标注者姓名—案例序号范围”，不要两个人同时标同一案例。
- 各自按分配范围使用“下一例”，不要用“下一未完成”跨到别人的范围。
- 遇到不确定情况按规则选择 `UNCERTAIN`/`INSUFFICIENT` 并写原因，不要为了完成而强行判断。
- 不讨论尚未标注案例的答案，避免互相影响盲标。

## 一句话原则

**先判断当前 mask 是否代表一个独立物理实例，再判断事件前候选中是否已经存在同一个现实物体；局部可见不等于粒度歧义，同类相邻也不等于同一实例。**
