# 实验 0：Room0 人工标注驱动回放——阶段 1 审计

## 当前结论

**状态：机制部分成立，但尚不能进入“方法整体可行”或修改生产默认逻辑。**

人工标注已经可以稳定指出当前路由应当 `NEW` 还是 `ATTACH_EXISTING`，约束也能在真实在线 mapper 中安全执行。但最新的全成员审计证明：仅检查少量人工探针会高估修复效果。对已经混合的候选实例，在较晚错误帧执行一次 `CREATE_INSTANCE` 只能形成高精度的新子簇，无法召回此前及此后的全部同实例观测。

## 1. 标注输入与质量

- 完成 179/179 条标注：162 个独立主样本，17 个盲重复。
- 162 个独立样本中，158 个 `CLEAN + COMPLETED`，4 个背景等无效项按规则排除。
- 盲重复的路由、可判定性、mask 质量和实例身份结论一致率均为 100%。
- 精确候选集合一致 15/17；所有核心细字段完全一致 14/17。少量细粒度差异不改变路由结论。
- 113 个可直接比较样本中，人工路由与离线私有 GT 的方向一致率为 100%。
- 自然概率队列 148 个有效样本中发现 5 个错误，错误率 3.378%，Wilson 95% 区间约 1.45%–7.66%。
- 合并主批次与有效 R2 裁决后得到 174 个独立事件、14 个人工错误：
  - 7 个本应新建；
  - 2 个关联到了错误的已有实例；
  - 5 个本应关联已有实例却错误新建。

注意：上述证据支持“当前 observation 的路由标签”。最新审计发现，D 阶段的候选历史展示可能系统性低估已有混合，因此此前导出的 7 个根错误、6 个连锁错误、1 个待定仍需按完整目标成员重新审计，暂不能作为最终因果统计。

## 2. 回放实现

所有正式回放都从 frame0 在线重建到锚点前，未使用最终地图作为起点。

- `B0`：原始最终状态。
- `B1`：只修改锚点成员归属，后续决策冻结；仅作诊断，不是几何有效地图。
- `B0R`：无约束重放控制，必须精确复现 B0 分区。
- `B2`：人工约束 + 类型化依赖闭包重放。
- `B3`：相同约束 + 锚点后完整后缀重放。

未来视角和 observation GT 只用于回放结束后的评价，不进入约束、候选选择或在线 mapper。每次完整运行只在开始和结束各核验一次源证据，避免重复哈希。32 项相关测试全部通过。

服务器新 CUDA 进程存在驱动初始化失败，本阶段使用 CPU；未重置 GPU，也未改动源数据。

## 4. 已确认的机制问题

### 4.1 污染历史边界会反向恢复错误

0143 在 frame325 的自然 matcher 本来选择新实例：

- 新实例分数：1.986；
- 旧目标分数：1.878；
- 阈值：1.2。

但逐 observation CREATE 身份边界读取原始错误历史，将该 observation 解释为旧目标身份，禁止选择新实例。关闭这一层、保留后处理防合并边界后，325、333、339、340 都自然进入新实例；防合并边界实际阻止了 16 次潜在重新合并。

因此默认边界的失败不是闭包过小、候选不足或 matcher 无法区分，而是把已污染历史当作真值。

### 4.2 探针 endpoint 会高估整实例修复

`v2_r2_013` 的三条评测探针全部正确，B2 与 B3 endpoint 都为 `true`，但全成员结果为：

- 原始受影响分区：252 条；
- GT=15：129 条；
- GT=19：115 条；
- GT=21：8 条；
- 新实例：16 条，16/16 为 GT=19；
- 新实例精度：100%；
- 对 GT=19 的整实例召回率：16/115 = 13.91%；
- F1：0.244；
- 仍留在旧目标中的 GT=19：99/115 = 86.09%。

B2 与 B3 最终分区完全一致，说明低召回不是局部闭包裁剪造成，而是“在当前帧单点新建”这个修复原语不足。

对 frame253 之后 91 条 GT=19 决策逐条检查：

- 新实例进入候选 90/91 次；
- 新实例达到阈值 77/91 次；
- 旧混合目标达到阈值 91/91 次；
- 自然 matcher 选择旧目标 76 次，选择新实例 15 次。

例如 frame255 中，新实例得分 1.259、旧混合目标得分 1.944；frame256 分别为 1.292 与 1.963。旧目标已积累大量两个实例的几何与外观，因而对 GT=19 仍具有更高吸引力。这进一步说明：低召回不是新实例没有成为候选，而是混合目标产生了自强化路由。较晚单点新建无法消除这种历史优势。

### 4.3 标注为 CLEAN 的候选其实已经混合

013 在人工错误帧 253 前的目标版本共有 132 条成员：

- 108 条 GT=15；
- 24 条 GT=19。

人工 D 阶段记录为 `CLEAN_SINGLE_INSTANCE`，但完整成员显示已有 18.18% 的另一实例。最早引入 GT=19 的成员是 frame138 的 observation：

- obs：`room0_20260831T111035Z_5c9d86fa_f000138_r0016`；
- event：`room0_20260831T111035Z_5c9d86fa_e00005670`；
- 原动作：`MERGE_TO_OBJECT`；
- top1：1.800；
- threshold：1.2；
- 目标版本在该事件前为 12 条 GT=15，12/12 单一实例。

但 frame138 不是一个可以整体执行 `NEW` 的纯 observation。它的 mask 同时覆盖两扇同类百叶窗：GT=19 占 48.98%，GT=15 占 46.06%，并被离线审计标为 `mask_mixed=true`、`mask_two_foreground=true`。整张 mask 若 `ATTACH` 会把 GT=19 污染旧窗；整张 mask 若 `NEW` 又会错误带走 GT=15。它需要的上游修复原语是“拆分或隔离混合 mask，再分别 ATTACH/NEW”。

这表明 frame138 才是当前可见的最早污染点，而且根因属于 segmentation-origin identity contamination。它不在现有 174 条路由标注中；frame253 是晚期症状，不应作为根错误修复锚点。现有协议将混合 mask 排除出身份路由统计，保证了路由标签清晰，却也因此无法覆盖所有身份污染的真正起点。

0143 也存在同类警告：人工目标状态为 `CLEAN_SINGLE_INSTANCE`，但锚点前目标版本的可靠成员已包含 336 条 GT=9、206 条 GT=8 及少量其他 ID。由于该例原目标 GT 无法可靠确定，0143 只能作为人工探针与机制诊断证据，不能报告 GT 实例级完整恢复。

## 5. 目前可以与不可以声称什么

可以声称：

1. 标注可用于当前帧身份路由错误识别和约束编译。
2. `ASSIGN_OBSERVATION` 与 `CREATE_INSTANCE` 均可在真实 mapper 中执行，且已验证运行安全性与范围外不变性。
3. 去除受污染历史的逐 observation CREATE 边界后，系统能够形成高精度的新身份子簇，并由自然 matcher 持续吸收一部分后续观测。
4. 完整成员审计能够发现探针 endpoint 的乐观偏差。

不能声称：

1. 当前 CREATE 修复已经恢复完整物理实例。
2. 013 是第二个完整成功正例。
3. 人工 D 阶段的根/连锁判断已经可靠。
4. 当前机制可以修改为生产默认逻辑。
5. room0 单场景 oracle 结果可以泛化到其他场景或自动错误发现。

## 6. 下一步判据

1. 将 frame138 最早污染事件加入新的盲标批次，不向标注员显示 GT 结论，先确认人工能否稳定识别 `MIXED_MULTI_INSTANCE`。
2. 先做明确标为诊断上限的 oracle split：将混合 observation 拆成两个实例片段，GT=15 片段关联原目标、GT=19 片段新建，再从真正污染起点回放。oracle split 不作为可部署方法，只回答“根部正确拆分是否足以恢复整实例”。
3. 再研究不使用 GT 的拆分实现，例如 2D 连通区域、深度/3D 不连续性或重新分割；只有它接近 oracle split 才构成实际修复方案。
4. 主要指标改为全实例 observation 级 precision、recall、F1、旧目标残余污染和范围外变化；探针 endpoint 只保留为辅助指标。
5. 若根部拆分后仍有低召回，再进入“拆分已混合目标 + 历史成员重定向”原语，而不是继续增加单帧 CREATE 约束。
6. 重新设计 D 阶段目标历史展示，使其覆盖候选成员的时间、空间和外观多样性；复核根/连锁标签。
7. 只有根错误回放达到高精度、高召回、B2/B3 一致且负例无退化后，才考虑跨场景 office0/room2 和生产默认修改。
