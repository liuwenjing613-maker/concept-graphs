# 实验 0：room0 混合实例根因与修复上限阶段结论

## 一句话结论

**标注已经足以揭示并评测这类错误；“混合证据隔离 + 等待纯净证据创建新实例 + 身份边界低分差连续性”在 room0 的 oracle 条件下可以完整修复，但在线混合检测和跨实例阈值尚未验证，因此现在只能判断核心机制可行，不能宣称完整方法已经成立。**

## 1. 已使用的标注与统计基础

- room0 正式大队列：179/179 条完成，其中 162 个独立样本、17 个盲重复。
- 盲重复：路由标签、是否可纳入路由、observation quality 一致率均为 1.000；候选集合一致率 0.882。
- 与 R2 去重合并后：174 个独立事件，识别出 14 个错误 episode：7 个 SHOULD_NEW、2 个 WRONG_ATTACH_EXISTING、5 个 WRONG_NEW_FALSE_SPLIT。
- 可估计自然发生率的 150 个概率抽样事件中，148 个可裁决，确认 5 个错误；可裁决事件错误率 3.38%，95% Wilson 区间约为 1.45%–7.66%。

这些标签不只给出“对/错”，还提供 observation 质量、正确路由、同实例候选和证据充分性，因此可以用于定位错误发生在哪一层，而不是只统计最终错误率。

## 2. 为什么最初的 CREATE 修复不成立

困难案例 `v2_r2_013` 的完整分区审计显示：虽然局部探针看似通过，新实例对 GT19 的召回率只有 13.91%，F1 只有 0.244。绝大多数 GT19 observation 仍留在旧混合实体里。

进一步检查根帧 frame138 后发现：

- 该 processed mask 约含 GT19 48.98%、GT15 46.06%，属于两个前景实例的混合 mask。
- 对整个 mask 执行 ATTACH 或 NEW 都不正确；正确动作需要先隔离或拆分混合证据。
- 单独隔离 frame138 后完整回放，GT15 与 GT19 的最佳实体仍是同一个，F1 没有提升。

因此根因不是单次身份路由错误，而是上游分割持续把两个同类相邻实例混在一起。

## 3. 时序证据

校正 GT 只在回放完成后用于审计。frame138 之后：

- 同时包含 GT15/GT19 的混合 observation 共 168 个，分布在 frame138–343。
- 除被隔离的 anchor 外，其余 167 个混合 observation 全部自然 ATTACH 到旧实体。
- 严格纯净 observation 共 24 个：GT15 为 7 个，GT19 为 17 个。
- 首个纯净 GT15 在 frame222，首个纯净 GT19 在 frame253。
- 24 个纯净 observation 在原 matcher 中仍全部进入同一个旧实体。

这证明两点：只删一个坏帧不够；只等待纯净帧也不够，因为 matcher 不会自行产生新的身份边界。

## 4. 最小上限实验

所有分支都从同一个严格 pre-frame138 快照开始；运行输入遵循在线时序，未来 GT 不进入 matcher。oracle 仅用于事先选出 168 个混合 observation 和第一个纯净 GT19。

| 分支 | 干预 | GT15 P/R/F1 | GT19 P/R/F1 | 两实例分开 |
|---|---|---|---|---:|
| B0 | 原始端点 | 0.469/1.000/0.638 | 0.531/1.000/0.694 | 否 |
| Q2 | 只过滤 168 个混合 observation | 0.469/1.000/0.638 | 0.531/1.000/0.694 | 否 |
| Q3 | Q2 + 在 frame253 首个纯净 GT19 上 CREATE 一次 | 0.938/1.000/0.968 | 1.000/0.941/0.970 | 是 |
| Q4 | Q3 + 低分差身份连续性消融 | 1.000/1.000/1.000 | 1.000/1.000/1.000 | 是 |

Q3 中，CREATE 后 16 个纯净 GT19 有 15 个自然进入新实体。唯一残差是 frame258：旧实体得分 1.9074，新实体得分 1.8812，仅相差 0.0261。

Q4 的选择器不读取 frame258 的 GT，只检查已经建立身份边界的两个候选：两边都合格、旧边胜出且领先不超过 0.03 时保持新身份连续性。本次 trace 中：

- 两边都合格：26 个 observation；
- 旧边胜出：11 个；
- 领先不超过 0.03：只有 frame258 这 1 个；
- 下一小的旧边领先幅度为 0.6564。

Q4 后 16/16 个后续纯净 GT19 属于新实体，GT15/GT19 的完整可靠分区均为 P=R=F1=1.000。

## 5. 执行正确性

- Q2/Q3/Q4 均回放 4969 个保留 observation，状态为 COMPLETED。
- 三个分支的所有权与运行时不变量均通过。
- 受影响集合之外改变的 observation 数均为 0。
- 没有重复 owner、未知 observation 或外围分区变化。
- 源证据结束校验未改变；只在构建上下文和最终结束各校验一次。

因此上述差异来自规定的干预，而不是脏状态、未来数据泄露或外围重写。

## 6. 现在能说明什么

可以说明：

1. 人工标注设计能够支持实验 0 的错误类型、根因层级和修复结果判断。
2. 对持续混合实例，单纯修改 ATTACH/NEW 路由不够；必须加入 observation 质量门控或实例拆分。
3. 在理想混合门控下，一次纯净 CREATE 能建立稳定的新身份，15/16 个后续纯净 observation 无需逐帧人工路线即可自然延续。
4. 低分差的身份边界连续性是一个有价值的新修复假设，本例可消除最后一个残差。

仍不能说明：

1. 系统已经能在线识别 168 个混合 observation；当前选择来自校正 GT。
2. `0.03` 是通用阈值；它是在本例结果上事后提出的。
3. 大量过滤不会损害地图完整性；当前完整实例指标有意排除了混合 observation。
4. 方法能跨错误、跨实例、跨场景稳定工作。

所以最准确的判断是：**核心修复机制获得了强单例可行性证据，但完整在线方法尚未验证。**

## 7. 下一步

1. 冻结一个不读 GT 的混合风险信号，优先使用候选竞争、身份边界冲突和短时一致性；历史几何尾部已在正常视角扩展上出现大量误报，不能单独作为判据。
2. 把“过滤”改成可恢复的延迟证据缓冲：混合 observation 暂不写入实体，但保留供后续重分割或分配，避免永久丢失 168 个观测。
3. 在其他 SHOULD_NEW 根例和纯净负例上验证身份边界分差；阈值必须在开发样本冻结后再进入未见场景。
4. 增加地图覆盖率、几何完整度和误隔离率指标，不能只看纯净身份分区。
5. 通过上述开发验证后，再对 office0/holdout 做严格在线运行，报告成功、退化和失败。
